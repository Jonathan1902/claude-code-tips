Dica #10 — Memória entre Sessões

  • Por padrão, cada sessão começa do zero — o agente não tem memória persistente entre conversas
  • O CLAUDE.md é a forma mais simples de memória: tudo que está nele é carregado em toda sessão do projeto
  • O comando /memory permite salvar fatos que o agente recupera automaticamente nas próximas sessões

O que é memória no Claude Code?

Memória = informação salva em arquivo que o agente carrega automaticamente na próxima sessão.
  • O modelo em si não guarda nada — cada sessão começa com o contexto em branco
  • A "memória" existe em arquivos que o agente lê no início de cada sessão
  • Você decide o que vai para o CLAUDE.md, o que vai para /memory e o que fica só na sessão atual

Três formas de memória

Cada uma serve a um propósito diferente

📄 CLAUDE.md Carregado automaticamente em todo projeto. Ideal para stack, restrições e convenções fixas do time.
🗂️ Arquivos de memória (/memory) Fatos e preferências que evoluem ao longo do tempo. Salvos e recuperados pelo agente sob demanda.
💬 Contexto da sessão Existe apenas enquanto a conversa está aberta. Não persiste — se fechar, sumiu.

O que vai para onde?

Exemplos do mercado financeiro

  • CLAUDE.md: "Modelos de risco nunca usam dados após o corte regulatório" — regra do projeto, sempre ativa
  • Memória: "O time prefere pandas a polars para relatórios" — preferência que pode mudar, registrada via /memory
  • Não precisa persistir: dúvidas pontuais de uma análise exploratória — fique no contexto da sessão
  • Não precisa persistir: rascunho de e-mail ou explicação de conceito — use o Chat Web

O que você leva daqui

  • O Claude Code não tem memória nativa — ela é construída com arquivos
  • CLAUDE.md para o que é fixo; /memory para o que evolui
  • Cada vez que você fecha o terminal, o CLAUDE.md é o que garante que o agente retome de onde parou
