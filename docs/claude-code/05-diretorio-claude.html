Dica #05 — O diretório .claude

.claude/ ├── settings.json ← permissões e variáveis de ambiente ├── hooks/ ← scripts automáticos por evento │ └── pre-commit.sh └── skills/ ← comandos customizados do agente └── meu-skill/ └── SKILL.md
  • .claude/ é a pasta de configuração do agente — análoga ao .github/ para Actions
  • Versionada junto com o código — toda a equipe herda as mesmas configurações automaticamente
  • Uma pasta, três camadas — a equipe toda herda as mesmas regras e automações sem configurar nada manualmente em cada máquina

O que cada peça faz

Configuração, automação e extensão em uma pasta só

  • settings.json — define quais ferramentas o agente pode usar (allowlist/denylist) e injeta variáveis de ambiente no contexto do Claude
  • hooks/ — scripts shell disparados em eventos do ciclo de vida do agente (antes de commitar, após editar um arquivo, ao finalizar uma tarefa). Exemplo: validar automaticamente um risk_model.py antes de qualquer commit
  • skills/ — comandos customizados em Markdown que ensinam ao agente fluxos específicos do seu projeto via slash commands (/meu-skill)

Três arquivos, três responsabilidades

Cada um cobre uma camada diferente do comportamento do agente

settings.json Governa o que o agente pode fazer. Allowlist de ferramentas, denylist de comandos sensíveis e variáveis de ambiente injetadas no contexto.
hooks/ Governa quando scripts externos rodam. Reações automáticas a eventos: pré-commit, pós-edição de arquivo, pós-tarefa concluída.
skills/ Governa o que o agente sabe fazer. Slash commands customizados que codificam fluxos de trabalho do time em instruções reutilizáveis.

.claude/ resolve o seu caso?

  • Resolve: validar arquivos de risco (ex: risk_model.py) com um hook antes de qualquer commit chegar ao repo
  • Resolve: restringir tools em produção via denylist no settings.json — o agente não pode deletar arquivos nem rodar migrações sem aprovação explícita
  • Não resolve: controle de acesso a nível de usuário — settings.json é por projeto, não por pessoa
  • Não resolve: segredos sensíveis como tokens de API — use um gerenciador de segredos externo, não o settings.json

O que você leva daqui

Qual arquivo você usaria para bloquear um comando perigoso no seu repo?

  • .claude/ é o hub central do agente no seu repo — configuração, automação e skills em um lugar só
  • Versionar .claude/ garante que todo o time opera com as mesmas regras — sem configuração manual por máquina
  • No mercado financeiro: use hooks para guardiões de qualidade e settings.json para limitar o raio de ação em ambientes críticos
