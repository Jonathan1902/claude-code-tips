O que é uma família de modelos?

Pense como categorias de atendimento: Haiku → Pronto-socorro: rápido, problema bem definido Sonnet → Clínico geral: resolve bem a maioria dos casos Opus → Especialista: diagnóstico profundo, porém mais caro Fable → Médico pesquisador: projetos longos, autonomia total
  • Modelos maiores raciocinam melhor em problemas ambíguos e longos — e custam mais por token
  • Modelos menores respondem mais rápido e gastam menos — suficientes para tarefas bem definidas
  • Claude Code expõe essa escolha via /model; o padrão é Sonnet
  • Curiosidade: Geralmente a cobrança é feita por token (entrada e saída), então usar o modelo certo gera economias significativas.

Fable vs Opus vs Sonnet vs Haiku

Perfis lado a lado para você decidir

🔬 Fable — Projetos longos e autônomos Autonomia máxima para tarefas estendidas e multi-etapas. Evite quando: o escopo é curto ou bem definido.
🧠 Opus — Raciocínio profundo Melhor em tarefas ambíguas e de alto risco. Custo mais alto por token. Evite quando: a tarefa é bem definida ou repetitiva.
⚖️ Sonnet — Padrão recomendado Equilíbrio entre qualidade e custo. Cobre a maioria dos casos. Evite quando: a tarefa é trivial (Haiku) ou exige análise crítica (Opus).
⚡ Haiku — Velocidade e economia Ideal para tarefas simples e repetitivas. Custo mais baixo por token. Evite quando: a tarefa é ambígua — erros podem custar retrabalho.

Como você usaria cada um?

  • Fable: orquestrar análises de risco multi-etapas ou processos autônomos de longa duração
  • Opus: geração de narrativas a partir de dados complexos — raciocínio profundo, vale o custo
  • Sonnet: refatorar pipeline de dados ou revisar lógica de regras de negócio
  • Haiku: geração de relatórios padronizados ou scripts de consulta a dados
  • Não faz sentido: usar Opus para formatar um CSV — Haiku resolve mais rápido e mais barato
  • Não faz sentido: usar Haiku para implementar lógica de negócio complexa de múltiplas regras
