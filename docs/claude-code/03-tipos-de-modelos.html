O que é uma família de modelos?

Pense como categorias de analistas: Sênior (Opus) → raciocínio profundo, hora mais cara Pleno (Sonnet) → resolve bem a maioria dos casos Júnior (Haiku) → rápido para tarefas bem definidas
  • Modelos maiores raciocinam melhor em problemas ambíguos e longos — e custam mais por token
  • Modelos menores respondem mais rápido e gastam menos — suficientes para tarefas bem definidas
  • Claude Code expõe essa escolha via /model; o padrão é Sonnet

Opus vs Sonnet vs Haiku

Perfis lado a lado para você decidir

🧠 Opus — Máxima capacidade Melhor raciocínio em tarefas ambíguas, longas e de alto risco. Custo mais alto por token. Evite quando: a tarefa é bem definida ou repetitiva — você pagará mais sem ganhar qualidade.
⚡ Sonnet — Padrão recomendado Equilíbrio entre qualidade e custo. Cobre a maioria dos casos de dev e automação. Evite quando: a tarefa é trivial (use Haiku) ou exige raciocínio muito profundo (use Opus).
🚀 Haiku — Velocidade e economia Respostas rápidas para tarefas simples e repetitivas. Custo mais baixo por token. Evite quando: a tarefa é ambígua ou exige interpretação — erros podem custar mais que a economia.

Como você usaria cada um?

  • Opus: análise de risco em portfólio complexo — raciocínio profundo, vale o custo
  • Sonnet: refatorar pipeline de dados ou revisar lógica de cálculo regulatório
  • Haiku: geração de relatórios padronizados ou scripts de compliance repetitivos
  • Não faz sentido: usar Opus para formatar um CSV — Haiku resolve mais rápido e mais barato
  • Não faz sentido: usar Haiku para interpretar regras de Basileia III em código legado
