Dica #08 — Slash Commands

Digite / seguido do comando para acionar atalhos direto no prompt

/help → lista todos os comandos disponíveis /clear → limpa o contexto da sessão atual /model → troca o modelo sem sair da sessão /init → gera o CLAUDE.md inicial do projeto /plan → modo planejamento: raciocina, não executa
  • /help sempre funciona — é o ponto de partida quando você travar ou quiser descobrir o que mais existe
  • /init lê o projeto e gera o CLAUDE.md automaticamente — faça isso no primeiro uso em qualquer repositório
  • Além dos built-ins, você pode criar commands próprios para fluxos recorrentes do time

O que são slash commands?

Atalhos que substituem instruções longas por uma palavra

Sem slash command: "Limpe o contexto, esquece tudo que falamos e começa do zero" Com slash command: /clear
  • Funcionam como macros de terminal: uma palavra dispara um comportamento completo
  • Comandos built-in vêm prontos — nenhuma configuração necessária
  • Comandos customizados são criados pelo time em .claude/skills/ para fluxos recorrentes

Built-in vs Customizados

Qual tipo resolve o seu caso?

⚡ Built-in (prontos) /help, /clear, /model, /init, /plan, /compact — funcionam em qualquer projeto, sem configuração. Use quando o fluxo é genérico: limpar contexto, trocar modelo, planejar antes de agir.
🛠️ Customizados (do time) Criados em .claude/skills/ como arquivos SKILL.md. Exemplo: /review-risco para análise de exposição, /gera-relatorio para gerar o relatório semanal de PnL. Use quando o fluxo é específico do negócio.

O que você leva daqui

Teste rápido: qual comando você usaria em cada situação?

  • Claude perdeu o fio da meada depois de muitas mensagens? → /clear reinicia sem fechar o terminal
  • Vai pedir uma mudança grande no código? → /plan primeiro: o Claude raciocina e pede aprovação antes de agir
  • O time repete o mesmo fluxo toda semana? → crie um command em .claude/skills/ e pare de digitar a mesma instrução
