Dica #07 — Como escrever prompts que funcionam

  • Seja específico: arquivo, função, comportamento esperado e restrições
  • Dê contexto suficiente: o que o código faz, o que não pode mudar, qual o ambiente
  • Peça um passo de cada vez — o agente erra menos quando o escopo é estreito
  • Mostre o formato esperado: "retorne um dict {ticker: var_pct}" elimina idas e vindas
# ruim: "refatora a função de risco" # bom: "Refatore a função `calc_var()` em `risk/models.py` para aceitar séries temporais de 5 anos sem alterar a assinatura pública. Não modifique os testes existentes."

O que é Prompt Engineering?

"A arte de estruturar instruções para que um agente de IA entenda exatamente o que você quer — e entregue sem adivinhar."
  • Com agentes de código, cada lacuna no prompt vira uma decisão autônoma do agente — sem supervisão sua
  • Não é sobre palavras mágicas — é sobre eliminar ambiguidade
  • Um prompt bom inclui: contexto · objetivo · restrições · critério de sucesso

Três níveis de prompt

A qualidade do output acompanha a qualidade do input

❌ Vago "melhora a performance do relatório" — o agente decide o que é melhorar, onde e como. Resultado imprevisível.
⚠️ Médio "otimize a query do relatório de PnL" — melhor, mas ainda sem critério de sucesso nem restrições de ambiente.
✅ Específico "Otimize a query em `reports/pnl.py` (linha 42) para rodar em menos de 2 s no PostgreSQL 15. Não altere o schema."

Quando vale detalhar o prompt?

  • Vale: refatorar `calc_var()` sem quebrar a assinatura pública usada por 3 módulos
  • Vale: gerar relatório regulatório onde o formato de saída é exigência de compliance
  • Vale: alterar lógica de precificação — qualquer erro tem impacto financeiro direto
  • Prompt curto basta: criar fixture de teste sem consequências — detalhar aqui é desperdício de tempo
  • Prompt curto basta: exploração inicial — deixe o agente propor e refine a partir da resposta

O que você leva daqui

Se o agente agir errado em produção, o prompt que você escreveu tem parte da culpa — o que você mudaria?

  • Prompt vago = agente adivinha = resultado imprevisível
  • Inclua: arquivo + função + restrições + critério de sucesso
  • Em código financeiro, ambiguidade vira bug silencioso — 30 segundos de prompt evitam horas de debug em produção
