Dica #03 — Permissões & Segurança

O agente age no seu repo — você decide até onde ele pode ir

  • O agente tem permissões granulares: leitura (baixo risco), edição (médio) e execução de comandos (alto) — cada nível exige um nível de controle diferente
  • O agente pede aprovação antes de ações destrutivas — mas você controla exatamente o que ele pode ou não tocar
  • Regra de ouro: nunca conceda permissão irrestrita em repositórios de produção — autonomia total só em ambiente de desenvolvimento

O que são permissões no Claude Code?

"Um conjunto de regras que define quais ferramentas o agente pode usar — e quando ele precisa da sua aprovação."
  • Ferramentas como leitura de arquivos, edição e execução de comandos têm níveis de risco diferentes
  • O modelo de permissões garante que ações de alto impacto nunca aconteçam sem a sua aprovação explícita
  • Configurável por projeto via .claude/settings.json — cada repositório pode ter sua própria política

Três modos de operação

Escolha o nível de autonomia do agente para cada situação

🛡️ Padrão (Default) Pede aprovação antes de editar arquivos ou rodar comandos. Máxima segurança — ideal para produção e repositórios críticos.
✏️ Auto-edit Edita arquivos sem pedir confirmação a cada mudança. Mais ágil para desenvolvimento — ainda exige aprovação em comandos de shell.
📋 Plan (Só planeja) O agente analisa o problema e descreve o que faria — sem executar nada. Ótimo para revisar estratégias antes de agir.

Onde usar cada modo no ambiente profissional?

  • Padrão: proteger arquivos de cálculo e regras de negócio — aprovação obrigatória antes de qualquer edição
  • Denylist: restringir escrita em /config/prod/ (configurações de ambiente de produção) — o agente nunca toca nesses caminhos
  • Plan: revisar a estratégia de refatoração de um motor de cálculo antes de o agente modificar o código
  • CI/CD: configure pipelines para exigir aprovação humana antes de deploys — não delegue esse controle ao agente
  • Cuidado com auto-edit em produção: repositórios com dados regulatórios sensíveis exigem aprovação em cada mudança
  • Cuidado com permissão irrestrita de deploy: comandos de publicação sempre devem passar pela sua aprovação explícita

O que você leva daqui

Você conseguiria explicar o modelo de permissões para um colega agora?

  • O Claude Code tem um modelo de permissões por ferramentas — não é acesso total por padrão
  • Escolha o modo certo para o contexto: padrão para repos críticos, auto-edit para dev, plan para revisar antes de agir
  • Comece pelo denylist: liste os caminhos críticos do seu repositório que o agente jamais deve tocar — ex.: /config/prod/, /migrations/
  • Use o modo Plan antes de agir em repos críticos — revisar a estratégia antes da execução reduz riscos de implementação
