Dica #06 — Sessões e Projetos

O que o Claude Code lembra — e o que você precisa gerenciar

  • Uma sessão começa quando você digita claude e termina quando você sai — o contexto não persiste automaticamente
  • Projetos (claude --project) associam uma sessão a um diretório com CLAUDE.md próprio
  • O histórico fica na janela de contexto — quando ela enche, o Claude comprime automaticamente
  • Para retomar: use /resume ou reabra o Claude no mesmo diretório — o CLAUDE.md recarrega o contexto

O que é uma sessão?

A unidade básica de trabalho com o Claude Code

$ claude # Sessão iniciada — contexto começa vazio # Tudo nessa conversa vive aqui dentro > /exit ← comando do Claude Code para encerrar # Sessão encerrada — histórico não persiste
  • Cada execução de claude é uma nova conversa — sem memória automática do que foi feito antes
  • O CLAUDE.md é o único mecanismo que persiste entre sessões — funciona como "briefing" automático para o agente
  • A janela de contexto tem limite — conversas longas são comprimidas automaticamente e detalhes antigos podem sumir

Sessão, Projeto ou /resume?

Cada modo serve a um tipo de trabalho diferente

⚡ Sessão simples — claude Trabalho pontual e isolado. Contexto limpo a cada abertura. Ideal para tarefas rápidas sem continuidade.
📁 Projeto — claude --project Associa a sessão a um diretório com CLAUDE.md próprio. Carrega contexto, regras e preferências do projeto automaticamente.
↩ Retomar — /resume Volta ao histórico de uma sessão anterior. Útil quando a janela de contexto foi interrompida no meio do trabalho.

Qual modo usar no seu trabalho?

  • Sessão simples: corrigir um bug pontual no módulo de cálculo de risco — sem precisar carregar todo o contexto do repo
  • Projeto: repositório de relatórios regulatórios de longa duração em compliance — regras e padrões persistem via CLAUDE.md
  • /resume: retomar uma refatoração grande interrompida no meio — o histórico da conversa é restaurado
  • Atenção: sem um CLAUDE.md configurado, preferências e padrões do projeto se perdem a cada nova sessão — crie um para cada repositório relevante
  • Atenção: contexto não é infinito — em sessões muito longas o agente comprime o histórico e detalhes do início podem desaparecer

O que você leva daqui

Pense num projeto real seu: qual desses modos você usaria amanhã?

  • Sessões são efêmeras — use para tarefas pontuais; não dependa de memória automática entre dias
  • Para repositórios de longa duração — compliance, modelos, relatórios — configure um CLAUDE.md e use --project
  • Interrompeu uma refatoração no meio? Use /resume para voltar exatamente de onde parou
